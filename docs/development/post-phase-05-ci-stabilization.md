## Independently reproduced failures

### 1. Migration/model defaults

The existing migration test reproduced `AutogenerateDiffsDetected` for all 16
reported columns. Migrations 0015/0016 already define the intended defaults; ORM
declarations omitted `server_default`. The repair retains each Python default and
adds the corresponding server metadata. No applied migration was rewritten and
`compare_server_default` remains enabled for the entire application schema.

The round trip now explicitly passes through 0016, inserts accepted history,
upgrades to head, checks that history survives, and performs the original complete
metadata check. A raw SQL regression inserts into all eight affected tables while
omitting all 16 fields, proving the database supplies the defaults without ORM
help. Its recovery-singleton replacement is transaction-local and rolled back.

### 2. Shared integration lease expiry

The old test expired only `IntegrationHeadModel.expires_at`, leaving the actual
`AcceptedTargetHeadModel.lease_expires_at` valid. Reacquisition correctly returned
`None`. The test now first proves that an expired run projection cannot steal a
valid shared lease, then expires shared authority without changing the run fence.

`accepted_target_heads`, keyed by repository and target branch, remains the sole
lease/head authority. A run's integration row records its last observed lease and
accepted result; its expiry alone never authorizes acquisition. Added cross-run
coverage proves FIFO order, higher replacement generations, stale renew/release
fencing and matching active projection/authority values. No run-only serialization
was restored and no integration-lease runtime change was necessary.

### 3. Diagnostics permissions

The original endpoint returned 500. Disposable PostgreSQL logged `permission
denied for table worker_invocations`; the SQL selected the full invocation model,
including private request/result JSON. The repaired query selects only
`last_activity_at` and `created_at`, joining `effect_id` through owner-scoped runs.

Forward migration 0017 grants only `SELECT (effect_id, created_at)` to the API
role. Existing activity/stall grants remain. Downgrade revokes exactly the new
columns. The readiness schema pin moves to 0017. No table-wide grant, privileged
endpoint connection, exception suppression or private-payload grant was added.

Tests execute the full diagnostics path under `jarvis_v1_api`, with empty and
populated invocation data, authentication rejection, another owner's exclusion,
timestamp fallback, real stalled observations, alert deduplication and recovery.
Direct reads of request/result/diagnostic JSON are denied by PostgreSQL.

### Additional runtime defect exposed by the rerun

The next targeted run failed both initial jobs with `security.policy_denied`.
The remote invocations had completed successfully, but runtime discarded their
results after the worker slot lease expired. Dispatch already renewed its slot
while awaiting SSH; reconciliation and collection did not. Artifact collection
can exceed the 30-second lease under load. The repair renews the existing fence
through reconciliation/collection and cancels the pending operation if renewal
fails. It does not increase TTL, revive expired leases, bypass generation checks,
or accept diagnostic-only results. Existing stale/cancelled-result tests remain.

A slow-collection regression uses a nine-second slot lease and twelve seconds of
collection. It maintains the enclosing run heartbeat separately, proves slot
renewal, and verifies normal terminal release. All seven worker integration tests
pass. An initial version incorrectly omitted the service's enclosing-run heartbeat;
a rerun against that failed run's database then encountered its still-queued work.
The corrected regression passed on a fresh disposable database.
